# 제네시스 GMR-001 · 특정 차량 형태를 유지하는 이미지 LoRA 학습

- **기간:** 2026.01 – 05
- **형태:** 개인 학습·생성 실험. 제조사 프로젝트나 공식 협업, 상용 배포가 아닙니다
- **시작 계기:** AI로 광고 영상을 1인 제작하면서 외부 생성 도구로는 특정 차량의 형태와 디테일을 컷마다 똑같이 유지할 수 없어서
- **도구:** ComfyUI, Flux, Z-Image

> 정량 성능 개선율은 산출하지 않았습니다. 비교는 육안 평가입니다.

## 요약

결과가 무너진 원인은 학습 설정이 아니라 데이터였고, 데이터를 다시 짠 뒤 같은 조건에서 베이스 모델만 바꿔 비교했습니다. Z-Image LoRA는 일관성이 무너져 공개하지 않았고, 공개한 모델은 Flux.2 Klein 4B-base 기반입니다.

### V2 데이터 구성

- **제외:** 여러 각도를 한 장에 합친 콜라주, 다른 차량이 화면 절반 이상을 차지한 사진 (다른 차의 특징까지 학습될 위험)
- **트리거:** `gmr001hypercar` 하나로 통일. 캡션에 섞여 있던 `gmr001`과의 중복 정리
- **캡셔닝:** VLM 자동 캡션으로 시작했다가 API 한도로 중단. 남은 이미지는 직접 작성하고 30장 전부 검수

### 캡션을 다시 쓴 기준

- **바꾸기 전:** 차량 고유 특징(도장, 번호, 로고, 램프)을 캡션에 적으면 모델이 그것을 "바꿀 수 있는 값"으로 학습합니다.
- **바꾼 뒤:** 도장·램프·로고는 트리거 단어에 묶고, 캡션에는 바뀌어도 되는 각도·배경·조명만 적었습니다.

## 베이스 모델 통제 비교

| 고정한 조건 | 값 |
|---|---|
| 데이터 | V2 이미지 30장 + 같은 캡션 |
| 생성 Step | 10 |
| CFG | 1 |
| LoRA strength | 1.10 |

바꾼 변수는 베이스 모델 하나입니다. A는 Flux.2 Klein 4B, B는 Z-Image Turbo이고, LoRA 가중치 20~40 구간을 5 단위로 바꿔 같은 프롬프트로 생성했습니다. Flux.2 Klein은 빠른 생성용 증류 버전이 아니라 Base 버전으로 학습했습니다. 증류 모델은 4스텝 생성에 맞춰져 있어 LoRA 적응에 불리하다는 점을 확인하고 골랐습니다.

### 비교 기준 다섯 가지

1. 형태 유지력: 차체 실루엣이 컷마다 유지되는가
2. 디테일 재현도: 램프, 에어로 파츠, 휠
3. 데칼 깨짐: 번호, 로고, 한글 레터링
4. 빛·하이라이트: 도장 반사가 자연스러운가
5. 스타일 확장성: 배경·질감 프롬프트를 따르는가

### 결과

| | 강점 | 약점 |
|---|---|---|
| A. Flux.2 Klein 4B | 원본 디테일 반영이 강함 | 질감 프롬프트를 무시하는 경우가 많음 |
| B. Z-Image Turbo | 질감·배경 프롬프트 반영이 좋음 | 원본 디테일 일부 손실 |

- 비교 시점의 육안 평가에서는 두 모델 모두 브랜드 특징인 Two-Line 램프를 유지했습니다.
- 이후 Z-Image LoRA는 일관성이 무너져 Civitai에 공개하지 않았습니다. 공개한 모델은 Flux.2 Klein 기반입니다.
- **남은 문제:** 두 모델이 같이 놓친 세부 디테일은 모델 차이가 아니라 30장 데이터의 한계로 판단했습니다. 해결하려면 근접 촬영 이미지 확보가 먼저입니다.
