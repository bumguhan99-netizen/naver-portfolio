# SSAFY AI 챌린지 2차 · 사진 속 글자를 읽어 답하는 VQA 모델 개선

- **기간:** 2026.09.20 – 09.28 (SSAFY 16기 2회차)
- **형태:** 팀 4인
- **과제:** 간판·가격표·메뉴 사진과 한국어 질문을 보고 보기 a~d 중 정답 고르기
- **내 역할:** 오류 원인 가설, 비교 조건, 채택 기준, 결과 판정, 사람 검수. 실험 코드 작성과 실행은 AI 코딩 에이전트에 맡김
- **기록 기준일:** 2026.11.08 정리한 통합 실험 기록

> 대회 데이터(이미지, 정답, 제출 파일)는 포함하지 않았습니다. 수치는 모두 기록에서 옮긴 값입니다.

## 요약

- 검증 정답을 627개에서 650개로 높임. 최종 결합 후보는 기존 결합 대비 교정 7, 악화 0
- 화면 글자는 전부 입력할 때보다 필요한 영역만 보여 줄 때 효과가 컸음
- 에이전트 실행 오류 2건을 직접 대조해 적발하고 재실행
- 라벨은 사람이 확인했고, 자동으로 고친 정답은 0건

## 3. 파이프라인

```
입력: 원본 이미지 + 한국어 질문 + 보기 a~d
 → 영역 찾기: PP-OCRv5(글자 영역), YOLO-World(간판·메뉴판 등 객체), SAM2.1(윤곽)
 → 글자 읽기: GLM-OCR로 crop 영역 인식, 이미지 hash 기준 캐시
 → 판단: Qwen3.5-9B가 원본, crop, OCR 문자열을 함께 보고 답 판단
 → 선택: a/b/c/d 첫 토큰 logits 비교, 여러 모델의 확률 결합
```

글자를 전부 입력하면 줄고 필요한 영역만 보여 줄 때 늘었지만, 읽기 실패, 대상 연결 실패, 답 범위 불일치 중 무엇이 원인인지는 직접 분리하지 못했습니다.

## 4. 외국어 장면

- 팀에 중국어·일본어·태국어·베트남어를 읽는 사람이 없어 새 라벨을 만들 수 없었습니다.
- 공식 원어 QA(MTVQA, EST-VQA, VinText)로 보조 학습하고, 학습과 분리한 39건으로 진단했습니다. 값은 공식 답과의 문자열 일치 수입니다.

| 입력 방식 | 문자열 일치 (39건) |
|---|---|
| 기본 입력 | 23 |
| 고해상도 | 26 |
| 글자 영역 확대 | 25 |
| OCR 문자열 주입 | 23 |
| YOLO / SAM 객체 영역 | 22 |

- YOLO는 39장 중 22장에서 상자를 찾지 못해 외국어 경로에는 적용하지 않았습니다.
- 외국어 39건의 고해상도 이득은 대회 673문항에서는 639 → 639로 이어지지 않았습니다.
- 작은 언어별 표본이라 전반적인 외국어 능력 향상으로 확정하지 않았습니다.

## 5. 에이전트 결과를 그대로 믿지 않아 적발한 두 번의 오류

1. **15%를 15개로 실행:** 외부 데이터를 15%, 30% 섞으라는 요청을 에이전트가 15개, 30개(실제 9.375%, 18.75%)로 실행. 그 결과는 보존하고 실제 15%·30%로 재실행.
2. **출력은 정상, 입력은 다른 대회 것:** 출력 개수·ID·해시는 모두 일치했지만 원본 SHA256 대조에서 test 6,714장 중 5,074장이 다른 대회 이미지로 확인됨. 정상 1,640장은 재사용하고 5,074장만 같은 설정으로 재추론.
   - 정정 후 1,878개 결합 규칙 중 1,017개의 답이 바뀌고 861개는 동일. 새 학습이나 라벨 변경은 없었음.
   - 출력 재현만으로 입력이 옳다고 판단할 수 없다는 교훈이 남음. 정확한 시간 손실과 점수 손실은 산정하지 않음.
